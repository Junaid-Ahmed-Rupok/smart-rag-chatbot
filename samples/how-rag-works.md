# How retrieval-augmented generation works

Retrieval-augmented generation, usually shortened to RAG, is a way of letting a language model answer questions about documents it was never trained on. Instead of hoping the model remembers a fact, the system looks the fact up first and hands it to the model together with the question.

## Step 1: Ingestion

Every uploaded file is read and cleaned. PDFs are read page by page so that each answer can point to a page number. Word documents and Markdown files are split at their headings so that an answer can point to a section. Scanned PDFs that contain only pictures of text cannot be read without optical character recognition.

## Step 2: Chunking

A whole document is too long to give to a model, and a model answers best from a short, focused passage. The text is therefore cut into chunks of roughly nine hundred characters. Neighbouring chunks overlap by about one hundred and fifty characters, so a sentence that falls on a boundary still appears whole in at least one chunk.

## Step 3: Hybrid search

Two kinds of search run side by side. Keyword search, using the BM25 formula, rewards chunks that contain the exact words of the question. Semantic search turns every chunk and the question into a vector of numbers, using a small embedding model, and finds the chunks whose meaning is closest. A vector index called FAISS makes that comparison fast. The two ranked lists are then merged with reciprocal rank fusion, so a chunk that scores well in both lists rises to the top.

## Step 4: Grounded answers

The best chunks are numbered and placed in the prompt. The model is told to answer only from those chunks and to cite them with numbers such as [1] and [2]. If the chunks do not contain the answer, the model must say so instead of guessing. The app also checks the match itself, and when nothing in the documents is relevant it declines to answer rather than invent something.

## Step 5: Checking the sources

Every citation in an answer opens the exact passage it came from, with the file name and the page or section. Reading that passage is the quickest way to confirm that the answer is faithful to the document.

## Limits to keep in mind

A RAG system can only be as good as the documents it is given. Tables and charts inside PDFs may be read badly. Very broad questions, such as asking for a summary of a long book, work better when the system samples passages from across the whole document. Answers are generated by a language model, so important facts should always be checked against the cited source.
